# XLeRobot 校准文件与归零姿态的区别

日期：2026-05-01  
校准文件路径：

```text
/home/mh/.cache/huggingface/lerobot/calibration/robots/xlerobot/my_xlerobot_pc.json
```

## 1. 核心结论

校准文件确实会被 XLeRobot host 加载，但它不是“归位姿态文件”。

校准文件保存的是：

```text
每个舵机的 ID
每个舵机的 homing_offset
每个舵机的 range_min
每个舵机的 range_max
drive_mode
```

它的作用是：

```text
把舵机原始编码值转换成 LeRobot/XLeRobot 软件里的 .pos 坐标。
```

它不保存：

```text
左臂应该回到什么姿态
右臂应该回到什么姿态
头部应该回到什么姿态
夹爪应该打开多少
机器人安全待机姿态
```

所以：

```text
校准 ≠ 归位
校准 ≠ Home Pose
校准 ≠ 安全零位
```

## 2. 代码哪里加载校准文件

XLeRobot 本体类在：

```text
E:\lerobot\lerobot\src\lerobot\robots\xlerobot\xlerobot.py
```

`connect()` 中有逻辑：

```python
if self.calibration_fpath.is_file():
    user_input = input(
        "Press ENTER to restore calibration from file, or type 'c' and press ENTER to run manual calibration: "
    )
    if user_input.strip().lower() != "c":
        self.bus1.calibration = {k: v for k, v in self.calibration.items() if k in self.bus1.motors}
        self.bus2.calibration = {k: v for k, v in self.calibration.items() if k in self.bus2.motors}
        self.bus1.write_calibration(...)
        self.bus2.write_calibration(...)
```

这说明：

```text
如果启动 host 时直接按回车，它会尝试从校准文件恢复 calibration。
如果输入 c，它会重新手动校准。
```

## 3. 为什么会觉得“没有引用校准文件”

因为你看到的是“归位动作”和校准文件不一致。

但脚本里的归位动作通常是这样写的：

```python
self.zero_pos = {
    "shoulder_pan": 0.0,
    "shoulder_lift": 0.0,
    "elbow_flex": 0.0,
    "wrist_flex": 0.0,
    "wrist_roll": 0.0,
    "gripper": 0.0,
}
```

然后：

```python
self.target_positions = self.zero_pos.copy()
robot.send_action(action)
```

含义是：

```text
把每个关节目标值设置为软件坐标 0。
```

不是：

```text
读取校准文件里保存的某个姿态，并回到那个姿态。
```

## 4. 校准时“放到中间位置”到底有什么用

校准过程里会提示：

```text
Move left arm and head motors to the middle of their range of motion and press ENTER.
```

这一步主要用于计算 `homing_offset`。

它的作用更接近：

```text
告诉软件：当前这个机械位置大致对应舵机的中心/半圈参考。
```

之后记录全行程：

```text
range_min
range_max
```

用于知道每个舵机的安全运动范围。

但这仍然不是在保存：

```text
以后按 reset 就回到这一次摆好的姿态。
```

## 5. 为什么归零会扭曲

常见原因：

```text
1. 代码把所有关节目标都设成 0。
2. 0 在软件坐标里只是一个数学参考点。
3. 你的机械安装方向、舵盘角度、连杆初始姿态可能和官方示例假设不同。
4. 双臂每个关节都设成 0 时，不一定是自然待机姿态。
5. 夹爪设成 0 也不一定是安全打开状态。
```

因此会出现：

```text
校准文件存在，也被加载了，但归零姿态仍然看起来扭曲。
```

这不是校准文件没用，而是脚本里的“归零目标”不适合你的机械结构。

## 6. 正确做法：单独定义 Home Pose

应该把“校准”和“安全待机姿态”分开。

校准文件负责：

```text
坐标转换
行程范围
homing offset
```

Home Pose 文件负责：

```text
左臂安全姿态
右臂安全姿态
头部安全姿态
夹爪默认状态
```

例如可以保存：

```json
{
  "left_arm_shoulder_pan.pos": 0.0,
  "left_arm_shoulder_lift.pos": 35.0,
  "left_arm_elbow_flex.pos": -55.0,
  "left_arm_wrist_flex.pos": 20.0,
  "left_arm_wrist_roll.pos": 0.0,
  "left_arm_gripper.pos": 50.0,
  "right_arm_shoulder_pan.pos": 0.0,
  "right_arm_shoulder_lift.pos": 35.0,
  "right_arm_elbow_flex.pos": -55.0,
  "right_arm_wrist_flex.pos": 20.0,
  "right_arm_wrist_roll.pos": 0.0,
  "right_arm_gripper.pos": 50.0,
  "head_motor_1.pos": 0.0,
  "head_motor_2.pos": 0.0
}
```

注意：这些数值必须根据你机器人的实际姿态慢慢试出来，不能直接照抄。

## 7. 当前脚本的安全修改方向

当前 Xbox 脚本已经做了一个关键修正：

```text
启动时不再自动 move_to_zero_position()
```

原因：

```text
启动后强制所有关节去 0，会导致机械臂从当前姿态突然跑向一个不一定安全的数学零点。
```

更推荐：

```text
启动时读取当前 observation。
target_positions 初始化为当前 observation。
只有用户明确按某个键时才改变目标。
```

## 8. 判断校准文件是否被加载的方法

启动树莓派 host 时，如果出现：

```text
Press ENTER to restore calibration from file, or type 'c' and press ENTER to run manual calibration:
```

直接按回车。

如果 host 后续能正常显示：

```text
Calibration restored successfully from file!
```

说明校准文件已经加载。

如果没有看到日志，可以提高日志级别或在代码里临时打印：

```python
print(self.calibration_fpath)
print(self.calibration)
```

## 9. 后续建议

下一步建议做一个单独的 Home Pose 工具：

```text
1. 当前姿态满意时，保存 observation 中的关节 .pos 到 home_pose.json。
2. 归位时读取 home_pose.json。
3. 分多步、低速、逐渐移动到 Home Pose。
4. 不再使用所有关节 0 作为默认归位姿态。
```

这样结构会清楚很多：

```text
calibration 文件：负责坐标校准
home_pose 文件：负责安全归位姿态
teleop 脚本：负责手柄控制
```
