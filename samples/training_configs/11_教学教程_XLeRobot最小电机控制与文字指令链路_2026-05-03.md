# XLeRobot 最小电机控制与文字指令链路

日期：2026-05-03

本文记录本轮 LLM 控制调试中的底层研究成果。它不是官方最终 Agent 方案，而是一份教学材料：讲清楚怎样写一个最小控制程序，怎样把用户输入的文字变成安全动作，怎样通过 `XLerobotClient.send_action()` 把动作发给树莓派 host。

官方最终路线应优先使用 RoboCrew：

```text
LLMAgent + tools + RobotCamera + ServoControler
```

本文的意义在于理解底层链路。以后接 RoboCrew、VLA、策略服务器时，也需要知道这些动作最终会落到什么样的机器人控制接口上。

## 1. 当前控制架构

当前硬件分工：

```text
Windows 高性能电脑
  运行 client 脚本
  处理键盘、手柄、文字输入、视觉、模型推理
        |
        | 局域网
        v
树莓派 5
  运行 xlerobot_host
  连接 USB 舵机总线、摄像头、底盘轮子
        |
        v
XLeRobot 机械臂、头部、底盘
```

树莓派 host 启动命令：

```bash
cd ~/xlerobot-dev/lerobot
source .venv/bin/activate
python -m lerobot.robots.xlerobot.xlerobot_host
```

Windows 端最小 client 运行命令：

```powershell
E:\lerobot\envs\lerobot-gpu\Scripts\python.exe E:\lerobot\host_client_examples\simple_xlerobot_client_control.py
```

当前默认参数：

```text
树莓派 IP：192.168.10.239
机器人 ID：my_xlerobot_pc
```

## 2. 最小程序需要导入什么

最小 host/client 控制只需要两个类：

```python
from lerobot.robots.xlerobot import XLerobotClient, XLerobotClientConfig
```

含义：

```text
XLerobotClientConfig：保存连接配置，比如树莓派 IP、机器人 ID。
XLerobotClient：真正的客户端对象，负责 connect、get_observation、send_action、disconnect。
```

最小连接代码：

```python
from lerobot.robots.xlerobot import XLerobotClient, XLerobotClientConfig

config = XLerobotClientConfig(
    remote_ip="192.168.10.239",
    id="my_xlerobot_pc",
)

robot = XLerobotClient(config)
robot.connect()
obs = robot.get_observation()
print(obs.keys())
robot.disconnect()
```

这段代码只连接机器人并读取状态，不会让机器人运动。

## 3. observation 是什么

`robot.get_observation()` 会从树莓派 host 读取当前机器人状态。

常见字段：

```text
left_arm_shoulder_pan.pos
left_arm_shoulder_lift.pos
left_arm_elbow_flex.pos
left_arm_wrist_flex.pos
left_arm_wrist_roll.pos
left_arm_gripper.pos

right_arm_shoulder_pan.pos
right_arm_shoulder_lift.pos
right_arm_elbow_flex.pos
right_arm_wrist_flex.pos
right_arm_wrist_roll.pos
right_arm_gripper.pos

head_motor_1.pos
head_motor_2.pos

x.vel
y.vel
theta.vel

camera_0
camera_2
head
```

字段含义：

```text
.pos        关节位置，通常是校准后的角度语义值
x.vel       底盘前后速度
y.vel       底盘左右平移速度
theta.vel   底盘旋转速度
camera_*    摄像头图像
```

打印关键状态的函数：

```python
def print_observation_summary(observation):
    keys = [
        "left_arm_shoulder_lift.pos",
        "left_arm_elbow_flex.pos",
        "right_arm_shoulder_lift.pos",
        "right_arm_elbow_flex.pos",
        "head_motor_1.pos",
        "head_motor_2.pos",
        "x.vel",
        "y.vel",
        "theta.vel",
    ]

    for key in keys:
        if key in observation:
            print(f"{key}: {observation[key]}")
```

## 4. send_action 是什么

`robot.send_action(action)` 是 Windows client 发动作给树莓派 host 的核心接口。

`action` 是一个字典：

```python
robot.send_action({
    "x.vel": 0.05,
    "y.vel": 0.0,
    "theta.vel": 0.0,
})
```

这不是直接串口数据包，而是 LeRobot/XLeRobot 的高层动作包。树莓派 host 收到这个字典后，再转换成具体电机控制。

换句话说：

```text
Windows client 写 send_action 字典
树莓派 host 负责把字典变成硬件控制
Feetech 舵机寄存器写入发生在 host 内部
```

所以最小控制程序不需要直接操作串口，也不需要直接写 Feetech 的 `Lock`、`Goal_Position` 等寄存器。

## 5. 底盘最小控制

底盘使用速度字段：

```text
x.vel       前后
y.vel       左右平移
theta.vel   旋转
```

停止底盘：

```python
def stop_base(robot):
    robot.send_action({
        "x.vel": 0.0,
        "y.vel": 0.0,
        "theta.vel": 0.0,
    })
```

低速前进一小段：

```python
import time

def move_forward(robot, speed=0.05, seconds=0.5):
    start = time.perf_counter()
    while time.perf_counter() - start < seconds:
        robot.send_action({
            "x.vel": speed,
            "y.vel": 0.0,
            "theta.vel": 0.0,
        })
        time.sleep(0.05)

    stop_base(robot)
```

为什么要循环发送？

host 有安全机制，如果超过一段时间没有收到命令，会停止底盘。日志中出现过：

```text
Command not received for more than 500 milliseconds. Stopping the base.
```

所以速度类动作不应该只发一次，而应该在动作持续期间周期发送。

## 6. 头部最小控制

头部使用位置字段：

```text
head_motor_1.pos
head_motor_2.pos
```

当前实测语义：

```python
HEAD_PITCH_KEY = "head_motor_1.pos"
HEAD_YAW_KEY = "head_motor_2.pos"
HEAD_UP_SIGN = -1.0
HEAD_LEFT_SIGN = 1.0
```

抬头示例：

```python
def look_up(robot, step=8.0):
    obs = robot.get_observation()
    current = float(obs.get("head_motor_1.pos", 0.0))
    robot.send_action({
        "head_motor_1.pos": current - step,
    })
```

低头示例：

```python
def look_down(robot, step=8.0):
    obs = robot.get_observation()
    current = float(obs.get("head_motor_1.pos", 0.0))
    robot.send_action({
        "head_motor_1.pos": current + step,
    })
```

注意：电机方向和物理装配有关。如果方向反了，不要到处改代码，应该集中改符号常量。

## 7. 夹爪最小控制

夹爪也使用位置字段：

```text
left_arm_gripper.pos
right_arm_gripper.pos
```

右夹爪打开：

```python
def right_gripper_open(robot, step=8.0):
    obs = robot.get_observation()
    key = "right_arm_gripper.pos"
    current = float(obs.get(key, 0.0))
    target = min(100.0, current + step)
    robot.send_action({key: target})
```

右夹爪夹紧：

```python
def right_gripper_close(robot, step=8.0):
    obs = robot.get_observation()
    key = "right_arm_gripper.pos"
    current = float(obs.get(key, 0.0))
    target = max(0.0, current - step)
    robot.send_action({key: target})
```

夹爪必须做软限位：

```python
target = max(0.0, min(100.0, target))
```

这样可以避免重复输入“打开”时把目标值推得太远。

## 8. 用户文字如何变成动作

我们调试过的文字控制链路是：

```text
用户输入中文
  -> 解析成 ParsedCommand
  -> 检查 command 白名单
  -> 转成 send_action 字典
  -> 发给 robot
```

定义结构化命令：

```python
from dataclasses import dataclass

@dataclass
class ParsedCommand:
    command: str
    seconds: float = 0.8
    speed: float = 0.06
    head_step: float = 8.0
    gripper_step: float = 8.0
    reason: str = ""
```

定义安全白名单：

```python
SAFE_COMMANDS = {
    "status",
    "stop",
    "move_forward",
    "move_backward",
    "turn_left",
    "turn_right",
    "look_up",
    "look_down",
    "left_gripper_open",
    "left_gripper_close",
    "right_gripper_open",
    "right_gripper_close",
}
```

关键词解析：

```python
def rule_parse(text: str) -> ParsedCommand:
    lower = text.lower().strip()

    if "向前" in lower or "前进" in lower:
        return ParsedCommand("move_forward", reason="用户要求前进")

    if "往后" in lower or "后退" in lower or "倒退" in lower:
        return ParsedCommand("move_backward", reason="用户要求后退")

    if "抬头" in lower:
        return ParsedCommand("look_up", reason="用户要求抬头")

    if "低头" in lower:
        return ParsedCommand("look_down", reason="用户要求低头")

    if "右夹爪打开" in lower:
        return ParsedCommand("right_gripper_open", reason="用户要求右夹爪打开")

    return ParsedCommand("status", reason="没有识别到安全动作，改为查看状态")
```

## 9. ParsedCommand 如何执行

底盘动作执行：

```python
def execute_base(robot, parsed):
    action = {"x.vel": 0.0, "y.vel": 0.0, "theta.vel": 0.0}

    if parsed.command == "move_forward":
        action["x.vel"] = parsed.speed
    elif parsed.command == "move_backward":
        action["x.vel"] = -parsed.speed
    elif parsed.command == "turn_left":
        action["theta.vel"] = 18.0
    elif parsed.command == "turn_right":
        action["theta.vel"] = -18.0

    start = time.perf_counter()
    while time.perf_counter() - start < parsed.seconds:
        robot.send_action(action)
        time.sleep(0.05)

    stop_base(robot)
```

头部动作执行：

```python
def execute_head(robot, parsed):
    obs = robot.get_observation()

    if parsed.command == "look_up":
        current = float(obs.get("head_motor_1.pos", 0.0))
        robot.send_action({"head_motor_1.pos": current - parsed.head_step})

    elif parsed.command == "look_down":
        current = float(obs.get("head_motor_1.pos", 0.0))
        robot.send_action({"head_motor_1.pos": current + parsed.head_step})
```

夹爪动作执行：

```python
def execute_gripper(robot, parsed):
    obs = robot.get_observation()

    if parsed.command == "right_gripper_open":
        key = "right_arm_gripper.pos"
        current = float(obs.get(key, 0.0))
        target = min(100.0, current + parsed.gripper_step)
        robot.send_action({key: target})

    elif parsed.command == "right_gripper_close":
        key = "right_arm_gripper.pos"
        current = float(obs.get(key, 0.0))
        target = max(0.0, current - parsed.gripper_step)
        robot.send_action({key: target})
```

## 10. 为什么默认要 dry-run

文字控制机器人时，默认应该不动，只打印解析结果。

```text
[LLM-COMMAND] ParsedCommand(command='move_forward', ...)
[DRY-RUN] 未加 --execute，不发送机器人动作。
```

只有显式加：

```powershell
--execute
```

才真正调用：

```python
robot.send_action(...)
```

原因：

```text
防止用户打错字导致误动作
防止大模型解析错意图导致误动作
防止脚本刚启动就动
方便先检查 ParsedCommand 是否合理
```

## 11. 大模型解析的正确边界

我们测试过 `rule` 和 `openai-compatible` 两种方式。

`rule`：

```text
不用模型，只靠关键词解析
适合先验证控制链路
```

`openai-compatible`：

```text
可接 Ollama / LM Studio / vLLM / OpenAI 兼容接口
```

重要原则：

```text
大模型只能输出安全 command
不能让大模型直接输出电机字段
不能让大模型直接决定任意角度
```

模型应该输出 JSON：

```json
{
  "command": "move_forward",
  "seconds": 0.8,
  "speed": 0.06,
  "reason": "用户要求向前移动"
}
```

程序必须再次检查：

```python
if command not in SAFE_COMMANDS:
    command = "status"
```

## 12. 关于手臂动作的本轮结论

我们尝试过把“举手”写成：

```text
文字命令
  -> 末端上移
  -> 二维 IK
  -> shoulder_lift + elbow_flex + wrist_flex
```

这个方法参考了官方 SO100 末端控制示例：

```python
shoulder_lift, elbow_flex = inverse_kinematics(x, y)
wrist_flex = -shoulder_lift - elbow_flex + pitch
```

但它只能作为教学和链路验证，不应作为最终手臂控制路线。

原因：

```text
它是二维平面 IK，不是完整 6D 末端位姿控制
主要涉及 2、3、4 号关节
不会自然协调 shoulder_pan、wrist_roll、gripper
复杂抓取不应该靠 LLM 临时算关节
```

官方更合理的路线是：

```text
LLM 选择工具
VLA policy 执行手臂操作
Windows GPU 跑 policy server
树莓派负责硬件 host
```

## 13. 最小完整模板

下面是一个可学习、可复制、可改造的最小程序。

```python
import argparse
import time
from dataclasses import dataclass

from lerobot.robots.xlerobot import XLerobotClient, XLerobotClientConfig


@dataclass
class ParsedCommand:
    command: str
    seconds: float = 0.8
    speed: float = 0.06
    head_step: float = 8.0
    gripper_step: float = 8.0


def rule_parse(text: str) -> ParsedCommand:
    if "向前" in text or "前进" in text:
        return ParsedCommand("move_forward")
    if "停止" in text or "停" in text:
        return ParsedCommand("stop")
    if "抬头" in text:
        return ParsedCommand("look_up")
    if "右夹爪打开" in text:
        return ParsedCommand("right_gripper_open")
    return ParsedCommand("status")


def stop(robot):
    robot.send_action({"x.vel": 0.0, "y.vel": 0.0, "theta.vel": 0.0})


def execute(robot, parsed: ParsedCommand):
    if parsed.command == "status":
        obs = robot.get_observation()
        print(obs.keys())
        return

    if parsed.command == "stop":
        stop(robot)
        return

    if parsed.command == "move_forward":
        action = {"x.vel": parsed.speed, "y.vel": 0.0, "theta.vel": 0.0}
        start = time.perf_counter()
        while time.perf_counter() - start < parsed.seconds:
            robot.send_action(action)
            time.sleep(0.05)
        stop(robot)
        return

    obs = robot.get_observation()

    if parsed.command == "look_up":
        current = float(obs.get("head_motor_1.pos", 0.0))
        robot.send_action({"head_motor_1.pos": current - parsed.head_step})
        return

    if parsed.command == "right_gripper_open":
        key = "right_arm_gripper.pos"
        current = float(obs.get(key, 0.0))
        target = min(100.0, current + parsed.gripper_step)
        robot.send_action({key: target})
        return


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--ip", default="192.168.10.239")
    parser.add_argument("--id", default="my_xlerobot_pc")
    parser.add_argument("--execute", action="store_true")
    parser.add_argument("--command", default="")
    args = parser.parse_args()

    text = args.command or input("你想让机器人做什么？> ")
    parsed = rule_parse(text)
    print(parsed)

    if not args.execute:
        print("dry-run：未发送动作")
        return

    robot = XLerobotClient(XLerobotClientConfig(remote_ip=args.ip, id=args.id))
    try:
        robot.connect()
        execute(robot, parsed)
    finally:
        if robot.is_connected:
            stop(robot)
            robot.disconnect()


if __name__ == "__main__":
    main()
```
