## 2. 摄像头链路里导入了哪些类和函数

### 2.1 配置阶段

文件：

```text
E:\lerobot\lerobot\src\lerobot\robots\xlerobot\config_xlerobot.py
```

导入：

```python
from lerobot.cameras.configs import CameraConfig, Cv2Rotation, ColorMode
from lerobot.cameras.opencv.configuration_opencv import OpenCVCameraConfig
```

用途：

```text
CameraConfig:
  LeRobot 的相机配置基类，XLerobotConfig.cameras 的类型就是 dict[str, CameraConfig]。

Cv2Rotation:
  设置图像旋转，例如不旋转、旋转 90/180/270 度。

ColorMode:
  设置相机输出颜色模式，例如 RGB/BGR。

OpenCVCameraConfig:
  OpenCV 摄像头配置类，用来描述 /dev/video0、/dev/video2 这类摄像头。
```

配置函数：

```python
def xlerobot_cameras_config() -> dict[str, CameraConfig]:
    return {
        "camera_0": OpenCVCameraConfig(...),
        "camera_2": OpenCVCameraConfig(...),
    }
```

这个函数不会直接打开摄像头，它只是返回“要打开哪些摄像头、使用什么参数”的配置。

### 2.3 host 连接阶段

文件：

```text
E:\lerobot\lerobot\src\lerobot\robots\xlerobot\xlerobot.py
```

调用：

```python
for cam in self.cameras.values():
    cam.connect()
```

每个 `cam` 实际是 `OpenCVCamera`。

`OpenCVCamera.connect()` 内部会：

```text
1. 调用 cv2.VideoCapture(index_or_path, backend)
2. 设置 FPS / width / height / FOURCC
3. 启动后台读帧线程
4. warmup 阶段等待第一批帧
```

如果 warmup 阶段等不到帧，就会报：

```text
TimeoutError: Timed out waiting for frame from camera ...
```

这就是 `/dev/video4` 头部摄像头刚才阻塞 host 的原因。

### 2.4 host 读取图像阶段

文件：

```text
E:\lerobot\lerobot\src\lerobot\robots\xlerobot\xlerobot.py
```

调用：

```python
def get_camera_observation(self):
    obs_dict = {}
    for cam_key, cam in self.cameras.items():
        obs_dict[cam_key] = cam.async_read()
    return obs_dict
```

关键函数：

```text
cam.async_read()
```

作用：

```text
从 OpenCVCamera 后台线程中拿最新图像帧，返回 numpy.ndarray。
```

### 2.5 host 编码并发送图像

文件：

```text
E:\lerobot\lerobot\src\lerobot\robots\xlerobot\xlerobot_host.py
```

导入：

```python
import base64
import cv2
```

调用：

```python
last_observation = robot.get_observation()

for cam_key, _ in robot.cameras.items():
    ret, buffer = cv2.imencode(
        ".jpg", last_observation[cam_key], [int(cv2.IMWRITE_JPEG_QUALITY), 90]
    )
    if ret:
        last_observation[cam_key] = base64.b64encode(buffer).decode("utf-8")
```

作用：

```text
1. robot.get_observation() 读到 numpy 图像。
2. cv2.imencode(".jpg", frame) 把 numpy 图像压缩成 JPEG。
3. base64.b64encode(...) 把 JPEG 二进制转成字符串。
4. 这样整个 observation 就能用 JSON 通过 ZMQ 发给 Windows。
```

### 2.6 Windows client 接收并解码图像

文件：

```text
E:\lerobot\lerobot\src\lerobot\robots\xlerobot\xlerobot_client.py
```

导入：

```python
import base64
import cv2
import numpy as np
import zmq
```

关键函数：

```python
def _decode_image_from_b64(self, image_b64: str):
    jpg_data = base64.b64decode(image_b64)
    np_arr = np.frombuffer(jpg_data, dtype=np.uint8)
    frame = cv2.imdecode(np_arr, cv2.IMREAD_COLOR)
    return frame
```

作用：

```text
1. base64 字符串还原成 JPEG 二进制。
2. np.frombuffer() 转成 numpy 字节数组。
3. cv2.imdecode() 解码成 OpenCV 图像 frame。
```

### 2.7 Windows 显示图像

文件：

```text
E:\lerobot\host_client_examples\摄像头画面查看器.py
```

导入：

```python
import cv2
from lerobot.robots.xlerobot import XLerobotClient, XLerobotClientConfig
```

核心流程：

```python
robot = XLerobotClient(XLerobotClientConfig(remote_ip=args.ip, id=args.id))
robot.connect()
obs = robot.get_observation()
```

显示：

```python
camera_names = [name for name, value in obs.items() if hasattr(value, "shape")]
for name in camera_names:
    frame = obs[name]
    cv2.imshow(name, frame)
```

为什么用 `hasattr(value, "shape")`：

```text
普通关节状态是 float，没有 shape。
摄像头图像是 numpy.ndarray，有 shape。
所以这样可以筛出图像帧。
```

## 4. 数据流

```text
树莓派 OpenCV 摄像头
  -> XLeRobot host get_observation()
  -> JPEG 编码
  -> base64 字符串
  -> ZMQ observation socket
  -> Windows XLerobotClient
  -> base64 解码为 OpenCV frame
  -> cv2.imshow 显示
```

## 6. 头部摄像头 /dev/video4 当前状态

`/dev/video4` 是第三路 USB2.0_CAM1，已经确认是头部摄像头。

`v4l2-ctl` 显示它支持：

```text
MJPG: 640x480 @ 30fps 等
YUYV: 640x480 @ 30fps 等
```

它曾在 XLeRobot host 里报过：

```text
Timed out waiting for frame from camera OpenCVCamera(/dev/video4)
```

单独排查结果：

```text
/dev/video4
MJPG
640x480
30fps
30/30 帧读取成功
```

新增单独排查工具：

```text
E:\lerobot\host_client_examples\树莓派头部摄像头排查工具.py
```

需要同步到树莓派后运行，例如：

```bash
python 树莓派头部摄像头排查工具.py --device /dev/video4 --fourcc MJPG --fps 30 --width 640 --height 480
```

可以尝试：

```bash
python 树莓派头部摄像头排查工具.py --device /dev/video4 --fourcc MJPG --fps 15
python 树莓派头部摄像头排查工具.py --device /dev/video4 --fourcc YUYV --fps 30
python 树莓派头部摄像头排查工具.py --device /dev/video4 --fourcc YUYV --fps 15
```

因此已把头部摄像头以 `head` 名称放回配置，并显式设置 `fourcc="MJPG"`，避免默认格式协商不稳定。

## 7. 注意事项

修改相机配置后，必须重启树莓派 host。

如果 Windows 查看器提示：

```text
no camera frames in observation
```

通常表示：

```text
1. 树莓派端还没有同步相机配置。
2. 树莓派 host 没有重启。
3. host 启动时摄像头打开失败。
4. Windows client 和 host 的 camera name 不一致。
```

## 8. 后续模型接入顺序

建议顺序：

```text
1. 先能显示 camera_0/camera_2/head。
2. 确认 camera_0 和 camera_2 分别是哪一路腕部或环境相机。
3. 给 camera_0/camera_2 改成语义名，比如 left_wrist、right_wrist。
4. 保存几帧样图确认方向和旋转。
5. 再接入模型的图像预处理。
6. 最后让模型输出 action。
```
