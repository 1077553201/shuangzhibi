## 1. 截图里的窗口是什么

截图中弹出的窗口是：

```text
Rerun Viewer
```

它不是报错，也不是机器人控制窗口。

它来自脚本里的两行代码：

```python
from lerobot.utils.visualization_utils import init_rerun, log_rerun_data

init_rerun(session_name="xlerobot_teleop_xbox")
...
log_rerun_data(obs, action)
```

作用：

```text
把 observation 和 action 记录成时间序列，并用图形界面显示。
```

你在窗口里看到的：

```text
observation.left_arm_elbow_flex.pos
observation.head_motor_1.pos
action.x.vel
action.theta.vel
action.left_arm_shoulder_lift.pos
```

这些就是机器人状态和控制命令的曲线。

## 2. 它有什么用

Rerun 可以帮助调试：

```text
1. 当前发给机器人的 action 是否乱跳
2. 某个关节目标值是否突然变大
3. 底盘速度是否没有及时归零
4. observation 是否正常回传
5. 模型或手柄输出是否稳定
```

所以它对开发很有用。

但在单纯遥控时，它也会占窗口和资源。如果暂时不想看，可以先注释：

```python
init_rerun(session_name="xlerobot_teleop_xbox")
```

以及：

```python
log_rerun_data(obs, action)
```

## 3. 小米手柄为什么会乱跳

当前脚本是按 Xbox 手柄布局写的，例如：

```python
axes[0] -> 左摇杆 X
axes[1] -> 左摇杆 Y
axes[2] -> 左扳机
axes[3] -> 右摇杆 X
axes[4] -> 右摇杆 Y
axes[5] -> 右扳机
buttons[0] -> A
buttons[1] -> B
buttons[2] -> X
buttons[3] -> Y
buttons[4] -> LB
buttons[5] -> RB
buttons[6] -> Back
buttons[9] -> 左摇杆按下
buttons[10] -> 右摇杆按下
```

小米手柄虽然外形可能接近 Xbox，但在 pygame/Windows 里暴露出来的编号可能不同。

常见问题：

```text
1. 左右扳机不是 axes[2]/axes[5]
2. 右摇杆不是 axes[3]/axes[4]
3. A/B/X/Y 编号不同
4. Back/Start 编号不同
5. 方向键不是 hat，而是 buttons 或 axes
6. 摇杆静止时不是 0，而是有轻微漂移
7. 扳机松开时可能是 -1、0 或 1，不同手柄不同
```

这些都会导致：

```text
脚本以为你按了某个键或拨了某个摇杆。
于是 action 不断变化，表现为机械臂或底盘乱跳。
```

## 4. 另一个乱跳来源：自动夹爪

当前脚本里有这段逻辑：

```python
if key_state.get('gripper+'):
    self.target_positions["gripper"] = 2
else:
    self.target_positions["gripper"] = 90
```

含义：

```text
只要没有按下 gripper+，夹爪目标就一直被设为 90。
```

这会导致即使你没有操作手柄，脚本也每一帧给夹爪发送目标值。

调试阶段建议改成：

```text
没有按夹爪键时，保持上一次目标值，不要自动改成 90。
```

## 6. 映射修正流程

第一步，记录小米手柄真实编号：

```text
左摇杆 X = axes[?]
左摇杆 Y = axes[?]
右摇杆 X = axes[?]
右摇杆 Y = axes[?]
左扳机 = axes[?] 或 button[?]
右扳机 = axes[?] 或 button[?]
A = button[?]
B = button[?]
X = button[?]
Y = button[?]
LB = button[?]
RB = button[?]
Back = button[?]
方向键 = hat[?] 或 buttons[?]
```

第二步，修改 `get_xbox_key_state()` 中的编号。

第三步，加入 deadzone：

```text
摇杆绝对值小于 0.15 或 0.2 时，当作 0。
```

第四步，把夹爪逻辑改成“按键才改变，不按保持”。

第五步，先只打印 action，不发送给机器人。

第六步，确认稳定后再发送给 host。

## 7. 安全建议

调手柄映射时建议：

```text
1. 先不要让机械臂上电动作。
2. 先用检测工具看编号。
3. 再让脚本只打印 action。
4. 确认 action 不乱跳后，再连接树莓派 host。
5. 第一次测试只让底盘低速动，不测试机械臂。
6. 机械臂测试时每次只开一个关节的小步长。
```
